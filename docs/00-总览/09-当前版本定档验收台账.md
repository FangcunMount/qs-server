## 9. 破坏性操作边界

本台账不授权任何生产 `DROP`、`DELETE`、Mongo collection 删除、Redis 批量清理、Attention apply 或 Statistics ledger 状态修改。

1. MySQL 物理删除前必须具备当前 schema/row count、备份、恢复命令、审批、执行窗口和执行后 migration/schema 核验。
2. Mongo 候选集合已有正式 archive 与 `mongorestore --dryRun` 证据，但仍需保留期限、精确对象清单和删除批准；备份成功不能替代实际恢复演练。
3. Redis 清理必须精确到 DB、family、namespace 和 key pattern；先证明旧实例退出并等待最长 data TTL。无 TTL token 只能单独审批，禁止宽泛通配删除。
4. Statistics running ledger 禁止批量改状态或先删锁；当前只读前提成立只意味着可以制定逐条处置方案。
5. Attention reconcile 当前只授权 dry-run。必须先取得当前 worker 部署、共享 leader、扫描清单和零写入证据；`dry-run=false` 需用户显式批准。

## 10. 定档签署条件

当前版本只有满足以下条件后才能从“阻断”升级：

- 全部 FINAL-P1 条目关闭，或形成包含 Owner、期限、指标和阈值的正式风险接受。
- 当前 HEAD 的全仓测试、必跑 CI、制品、实际 `DEPLOY_SHA` 和三进程运行指纹一致。
- Attention dry-run 在实际三 worker 环境完成并经原始指标/日志验收；apply 是否纳入本次定档由负责人显式决定。
- 六条 Statistics 陈旧 running ledger 逐条形成并执行获批处置，不留下无法解释的运行中状态。
- 每个活跃兼容项都有明确指标、Owner、观察窗与退出版本；生产物理候选保持“待批准”或在独立窗口完成退役闭环。
- 两份定档文档只保留当前有效事实，且与注册表、配置、组合根、迁移、API 生成结果、测试和生产证据一致。

目标模式继续按“只读验收 → 小批修复 → 聚焦测试 → Conventional Commit 类型前缀 + 中文主题 → push → CI/CD → 运行证据 → 更新台账”维护。每个可独立验收阶段立即提交，不跨阶段积攒；commit 或 push 本身不提升验收状态。
