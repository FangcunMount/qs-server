### 1.2 Outbox 背压容量边界

- Mongo durable Outbox store 注入共享 `MongoLimiter`，与其他 Mongo repository 共用 `backpressure.mongo.max_inflight` 预算。
- Assessment durable Outbox store 直接使用 GORM/MySQL，受 `mysql.max-open-connections` 约束，当前未注入共享 `MySQLLimiter`。
- 原启动校验错误地用 MySQL pool 同时限制两个 relay；本批改为 Mongo relay 对齐 Mongo backpressure、Assessment relay 对齐 MySQL pool，均保留 80% 上限。
- `internal/pkg/configcontract.MaxOutboxPublishWorkers` 原本没有任何运行调用，只由同包单测验证自身；真实 Options 边界测试已覆盖两类容量公式后，该重复 helper 与自证式测试确认删除。
- 生产配置 Mongo `publish_workers=8` / `max_inflight=120`，Assessment `publish_workers=24` / MySQL `max_open=150`，修正前后都满足上限，因此这是门禁语义修复，不是已发生的生产过载事故。
- 当前仍缺两个 relay 的生产 inflight、等待时长、claim 延迟与 MQ publish latency 关联证据；背压专题保持黄色“验收中”。

## 5. Survey 已成立的关键能力

### 5.1 可靠受理

- collection 只在 gRPC 返回非零 AnswerSheet ID 后返回 `202 Accepted`。
- BFF 强制精确 `questionnaire_code + questionnaire_version`、安全幂等键、ProfileLink 和 testee 访问校验。
- apiserver 在同一 Mongo transaction 中写 AnswerSheet 与 `domain_event_outbox`；`submit_meta` 嵌入 AnswerSheet。
- `(submit_meta.writer_id, submit_meta.idempotency_key)` 局部唯一索引是最终并发裁决；Redis 只负责合并压力。
- commit 结果未知时使用 detached readback，只有读到相同已提交事实才返回成功。

### 5.2 异步终点

- `answersheet.submitted` 在 [`configs/events.yaml`](../../configs/events.yaml) 中声明为 `durable_outbox`。
- worker 使用 `answersheet_processing` LockLease 做 best-effort 重复抑制，Redis 故障时降级开放，最终幂等由 Journey / Evaluation 事实保护。
- 新 AnswerSheet 冻结 admission；无 AssessmentModel binding 时标记 `independent_questionnaire`，Journey 完成基础计分后不创建 Assessment。
- 历史无 admission 事件仍走 live binding，因此“独立问卷终止”已对新写成立，但遗留入口尚未退出。

### 5.3 Questionnaire 发布与缓存

- head 与 immutable published snapshot 共用 `questionnaires`，正式 migration 保护 head、snapshot version 和 active code 唯一性。
- 已绑定问卷通过 Assessment Release 的 Mongo transaction 联合发布。
- apiserver Redis cache、collection L1、cache signal 和 warmup 已装配；缓存不是发布事实源。
- 独立 Questionnaire 的公开 `Publish` / `Unpublish` / `Archive` 使用 Mongo transaction；事件发布、缓存失效与信令在 commit 后执行。

当前源码与 migration 未发现 Survey 自有 Questionnaire/AnswerSheet MySQL 表。Survey 提交会读取 Actor/ProfileLink、Plan attribution，并向 Evaluation 派生事实；这些 MySQL 表属于对应模块，不能按 Survey 遗留表删除。

### 6.3 Redis / 临时事实

Questionnaire cache、提交 coalescer/完成信号和 `answersheet_processing` lease 都是可丢失的运行时机制，不是业务事实。删除或清空 Redis 不能替代 Mongo 幂等、Outbox、权限或迁移处理。
