### 1.2 Outbox 背压容量边界

- Mongo durable Outbox store 注入共享 `MongoLimiter`，与其他 Mongo repository 共用 `backpressure.mongo.max_inflight` 预算。
- Assessment durable Outbox store 直接使用 GORM/MySQL，受 `mysql.max-open-connections` 约束，当前未注入共享 `MySQLLimiter`。
- 原启动校验错误地用 MySQL pool 同时限制两个 relay；本批改为 Mongo relay 对齐 Mongo backpressure、Assessment relay 对齐 MySQL pool，均保留 80% 上限。
- `internal/pkg/configcontract.MaxOutboxPublishWorkers` 原本没有任何运行调用，只由同包单测验证自身；真实 Options 边界测试已覆盖两类容量公式后，该重复 helper 与自证式测试确认删除。
- 生产配置 Mongo `publish_workers=8` / `max_inflight=120`，Assessment `publish_workers=24` / MySQL `max_open=150`，修正前后都满足上限，因此这是门禁语义修复，不是已发生的生产过载事故。
- 当前仍缺两个 relay 的生产 inflight、等待时长、claim 延迟与 MQ publish latency 关联证据；背压专题保持黄色“验收中”。

### 1.3 Cache / Signal / Warmup 接口边界

- 当前 apiserver Router 与 OpenAPI 只通过 `GET /internal/v1/system-governance/cache` 暴露缓存状态，并通过统一 `system-governance/actions` 执行 manual warmup、repair complete 和 policy reload。
- 旧 `/internal/v1/cache/governance/status`、`/hotset`、`/warmup-targets` 均无注册路由、无 OpenAPI 定义；本批增加真实 Router 404 与 OpenAPI 缺席合同，分类为“已确认下线”，不是仍在使用的服务端兼容代码。
- qs-operating-system 当前应用代码使用 `/system-governance/cache`，旧菜单只做前端路由跳转；其 README 仍出现旧 status/hotset 路径，属于跨仓文档漂移，不能反向扩大 qs-server 兼容面。
- Redis Pub/Sub Signal 是 best-effort 本地预热唤醒，不是业务事实；Questionnaire、Scale、Typology 三类 typed signal 只在 `action=published` 时触发对应 target，durable consistency 仍由数据库事实和事件链承担。
- Warmup target 的 `static.scale`、`static.typology_model` 仍是公开 action 输入和指标 label；Questionnaire 精确版本失效还会 SCAN 当前 code family。两者需继续结合生产热度、指标与跨仓调用分类，本阶段不因旧命名或注释直接删除。
- 配置 Schema 与 CLI 已统一为 `cache.defaults...`、`cache.governance.warmup...`，但校验错误一度仍回显迁移前的 `cache.ttl_jitter_ratio`、`cache.warmup...`；本批已修正三条错误路径并增加 hotset retention cap 合同，旧配置 Schema 继续由 raw-settings 门禁拒绝。
- apiserver catalog 曾重复 re-export `PolicySwitchInherit`，活动代码、测试、配置和文档均无调用；shared kernel 的继承零值语义仍完整保留，本批只删除无消费者的内部目录别名，分类为“已确认可删除”。
- keyspace 的 `ApplyNamespace/AddNamespace` 只被同包测试调用，生产组合根始终通过 `redis_runtime.namespace + namespace_suffix` 构造显式 family Builder；本批删除旧 package-global namespace、其自证式测试和注释掉的 `prefix` 实现，未改变显式 namespace 或默认无 namespace 的 key 字节合同。

## 3. Survey 完成画像

### 3.1 入口与责任链

```text
Questionnaire authoring
  apiserver REST
  -> survey/questionnaire LifecycleService
  -> questionnaires head / published_snapshot
  -> cache invalidation + best-effort signal

AnswerSheet acceptance
  collection REST POST /api/v1/answersheets
  -> envelope + published questionnaire validation
  -> ProfileLink / testee ownership
  -> apiserver gRPC SaveAnswerSheet
  -> AnswerSheet + embedded submit_meta + domain_event_outbox transaction
  -> 202 Accepted

Async derivation
  answersheet.submitted
  -> worker duplicate-suppression LockLease
  -> Journey Ensure
  -> base scoring
  -> independent questionnaire ends, or bound questionnaire creates/submits Assessment
```

## 5. Survey 已成立的关键能力

### 5.1 可靠受理

- collection 只在 gRPC 返回非零 AnswerSheet ID 后返回 `202 Accepted`。
- BFF 强制精确 `questionnaire_code + questionnaire_version`、安全幂等键、ProfileLink 和 testee 访问校验。
- apiserver 在同一 Mongo transaction 中写 AnswerSheet 与 `domain_event_outbox`；`submit_meta` 嵌入 AnswerSheet。
- `(submit_meta.writer_id, submit_meta.idempotency_key)` 局部唯一索引是最终并发裁决；Redis 只负责合并压力。
- commit 结果未知时使用 detached readback，只有读到相同已提交事实才返回成功。

### 5.2 异步终点

- `answersheet.submitted` 在 [`configs/events.yaml`](../../configs/events.yaml) 中声明为 `durable_outbox`。
- worker 使用 `answersheet_processing` LockLease 做 best-effort 重复抑制，Redis 故障时降级开放，最终幂等由 Journey / Evaluation 事实保护。
- 新 AnswerSheet 冻结 admission；无 AssessmentModel binding 时标记 `independent_questionnaire`，Journey 完成基础计分后不创建 Assessment。
- 历史无 admission 事件仍走 live binding，因此“独立问卷终止”已对新写成立，但遗留入口尚未退出。

### 5.3 Questionnaire 发布与缓存

- head 与 immutable published snapshot 共用 `questionnaires`，正式 migration 保护 head、snapshot version 和 active code 唯一性。
- 已绑定问卷通过 Assessment Release 的 Mongo transaction 联合发布。
- apiserver Redis cache、collection L1、cache signal 和 warmup 已装配；缓存不是发布事实源。
- 独立 Questionnaire 的公开 `Publish` / `Unpublish` / `Archive` 使用 Mongo transaction；事件发布、缓存失效与信令在 commit 后执行。

## 6. Survey 数据对象盘点

### 6.1 MongoDB

| 集合 | 分类 | 当前写入 | 当前读取 | 结论 |
| --- | --- | --- | --- | --- |
| `questionnaires` | 当前业务事实 | 是 | 是 | 保留；包含 head 与 published snapshots |
| `answersheets` | 当前业务事实 | 是 | 是 | 保留；包含原始答案、派生题分、admission、attribution 和 `submit_meta` |
| `domain_event_outbox` | 当前技术恢复事实 | 是 | 是 | 保留；跨模块基础设施，不是 Survey 专属集合 |
| `answersheet_submit_idempotency` | 高置信遗留候选、生产未证实 | 否 | 是，嵌入元数据 miss 时 fallback | 不可直接删除；先完成生产盘点与迁移窗口退出 |

### 6.2 MySQL

当前源码与 migration 未发现 Survey 自有 Questionnaire/AnswerSheet MySQL 表。Survey 提交会读取 Actor/ProfileLink、Plan attribution，并向 Evaluation 派生事实；这些 MySQL 表属于对应模块，不能按 Survey 遗留表删除。

### 6.3 Redis / 临时事实

Questionnaire cache、提交 coalescer/完成信号和 `answersheet_processing` lease 都是可丢失的运行时机制，不是业务事实。删除或清空 Redis 不能替代 Mongo 幂等、Outbox、权限或迁移处理。
