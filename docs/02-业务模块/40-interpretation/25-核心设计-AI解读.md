# AI 解读：QS 桥接与旧引擎退役

## 1. 当前职责

qs-server 保留身份与主体授权、标准报告事实、可靠发起、结果接收与读取、管理接口代理。qs-ai 负责 Prompt、配置与评测发布、模型执行、恢复和结果投递。

标准报告读取已迁至 `internal/apiserver/application/interpretation/reportsource`；桥接位于 `internal/apiserver/application/aibridge`。旧 AI Generation、Run、Artifact、Profile、评测治理和 Mongo 仓储已删除，标准报告领域保持独立。

## 2. 接口与配置

参与者只使用 `ai-workflows` 三个入口。`ParticipantAIExplanationService` 的名称保持不变，只注册 `GetAIWorkflowSource`、`RequestAIWorkflow`、`GetAIWorkflow`。输出契约仍为 `ai-explanation-output/v1`。旧 REST 返回路由不存在，旧 RPC 不再注册。

新通信配置只使用 `ai_workflow.enabled` 与 `ai_workflow.management`，无旧配置别名。管理代理和参与者准入独立开关，共用 qs-ai 地址和 mTLS 文件。QS 不再注入模型密钥，也不注册旧 AI Worker handler、恢复器或六类旧 AI 事件。

## 3. 本批验证与发布边界

2026-09-15，代码删除版 d44ab9f 已在 API、两个 collection 和三个 Worker 上线；旧 REST 404、旧 RPC UNIMPLEMENTED、新链路终态及幂等复验通过。当前 v6 已有真实生成展示、授权撤销与恢复、结果重投证据，隔离恢复测试通过。证据仍按生产业务、服务边界和隔离测试分别记录，不再等待 24 小时。

代码发布与破坏性清库分开。旧消息须按六类事件定向排空后才能部署删除消费注册的版本；共享 NSQ Topic、Outbox、标准报告和新桥接数据保留。历史数据库迁移文件保留，新增 Mongo 35 退役迁移属于独立的清库后发布，任何非空旧集合都会拒绝迁移。备份和定向清库完成前不得合并部署该迁移。

数据库删除前固定白名单、数量及引用，并验证备份可恢复；备份保留 7 天。删除后不得直接回滚依赖旧表的镜像。

2026-09-15 用户明确调整发布顺序：先完成生产清库与服务端复验，小程序由用户最后正式发布。微信正式版不再阻塞清库，但正式发布及设备验收仍单独记录，不据服务端完成宣称已发布微信版本。

## 4. 历史资产

旧引擎设计归档（位于 `../../_archive/2026-09-m5/qs-legacy-ai-design.md`）保留迁移依据。`api/schema/interpretation` 只保留新链路成果所需的输出契约。旧 Prompt、评测和引擎专属规范已删除；归档中的相关链接固定到清理前提交，迁移基准由 qs-ai 维护。

## 方案工作区增量代理

`/internal/v2/interpretation/ai-workflow/solutions` 将方案列表、详情、原命令回执、模型能力和 create/save/prepare 转交 qs-ai 的 `SolutionManagement`。读沿用解读审计权限，写沿用 OrgAdmin；组织及操作者来自受保护上下文。QS 不保存方案副本，也不负责选择模型参数。

方案 prepare 在 qs-ai 内原子准备配置和待启动评测，不代表开始模型调用、审核通过或发布。响应不确定时必须核对原命令；QS 不自动重发写请求。三端按 qs-ai 增量能力、QS 代理、Operating 页面顺序发布。

### M3 T14：QS 事务命令候选

`MessagingCommandStore` 可显式借用同一原 MySQL 的 `CommandTransactionOwner`；未选择时保留旧链路的历史责任。事务适配不拥有 producer、连接池或 owner 的生命周期，宿主须登记完整 `qs.mysql` 事务Topic并管理 Start/Close。构造不访问数据库，启动只校验显式安装的108/42及现有档案/witness表。

命令在读取稳定幂等请求后，才规划聚合序号、首次时间及 Seal，复用原 `qs-ai-archive/v1` 格式。SDK完整reservation赢家冻结业务输入和首次wire；半消息全部成功后，原SQL根事务首先Bind guard，再重查准入、前序精确回执和序号，提交业务事实、operation、档案、计数器CAS与witness。Seal和MQ网络I/O不进入根事务。调用方已携带业务事务时，在查询、Seal和半消息之前拒绝；不另开一笔业务事务替代调用方原根。提交回复不明时查询精确witness；取消和callback错误均不直接等于回滚。真实在途root完成后才释放调用方等待，重复或迟到callback不能再开根事务。

同一聚合前一条命令须有持久 accepted/rejected 业务回执才能规划下一条；pending/held、损坏或已退役的前序均阻塞，TRANSACTION不充当FIFO或业务调度队列。并发冻结同序号只允许原事务CAS赢家提交，失败不会自动更换ID、重Seal或重执行业务。原operation查询和Payload RPC只在新档案与事务请求均不存在时读取历史Outbox；新档案须精确Committed witness并校验原租户、主体、聚合和正文hash，Prepared或损坏证据不回退。Participant的操作查询在业务request行尚不存在时，单独借用 `ReadPlannedStart` 校验冻结主体、testee/assessment绑定；当前访问授权失败（即使返回NotFound）不会进入计划读取。同一原请求重试复用首次冻结报告，不重新读取当前报告，不改变准入关闭时的既有操作。普通业务读取仍只认 `Store.Original` 的已提交事实。未提交的原计划公开为pending/transaction_pending，已中止为aborted/transaction_aborted，不返回已接受业务成功；本地Committed而Broker最终确认Unknown仍保留业务成功。

本批进度及证据由 [infra唯一执行总表](https://github.com/FangcunMount/infra/blob/main/docs/server/rocketmq-m3-execution.md) 维护。真实隔离profile `integration,m3_ai_command_broker` 使用原宿主命令入口、RocketMQ和MySQL；其前序receipt为受控夹具，observer只ACK，不计为AI成对接收器、数据库提交网络故障、进程退出、system或生产验收。接收AI事件后的事务ACK属T15，宿主全进程生命周期/运行诊断和最终切换属后续门禁，生产现有链路保持原状。

### M3 T15：QS 入站事件与事务 ACK 候选

`MessagingEventReceiver` 继续先校验实际逻辑路由、签名和精确正文，再借用与命令相同的 `qs.mysql` owner。冻结输入包含原入站 header/body/wire 的摘要；首次 ACK 的 ID、时间与 Seal 在 SQL 根事务之外完成。全部半消息准备成功后，原根事务首先取得 SDK guard，再提交 Inbox、原 receipt/状态投影、首次 ACK 档案和 witness。技术 HELD 只持久 Inbox 与 ACK，不应用业务投影；重复已提交事件核对首次 ACK 和精确证据，不重新准备半消息、不重做投影。回调/提交回复不明保持 Unknown，取消不充当回滚证明。

新的 command receipt 在同一原根连接读取精确命令 archive/witness；不另借连接，不要求新命令有 Outbox 行。真实历史命令继续原 Outbox 结算。历史 Inbox 不会被包装成新 ACK 事务证明，其原 ACK/Relay 责任必须在切换门禁完成交接。新选中的事务路径不启动旧 command/ACK Relay，原在途订阅预算仍为1。

只有当前经过认证的消费投递，才可显式授权精确 Aborted 的原投影执行重试；复用首次 ACK/wire，并保留旧 fence。若本地持久技术计数已改变为 HELD，则在精确 Aborted 后显式 Replan 并保留旧计划；Prepared/Unknown 不执行这一恢复。Checker 和维护循环不调用业务或模型。宿主传入已有业务事务时，普通接收、失败与隔离入口均在新增数据库根之前拒绝。

Payload 读取除检查命令请求外，还以有界的精确 owner/branch footprint 阻止 Prepared ACK 回退到历史正文；只有新档案、命令请求和出站分支均缺席才允许旧读取。新档案仍须精确 Committed witness、租户、工作负载和原正文 hash。

真实隔离 profile `integration,m3_ai_event_broker` 使用实际认证接收器、原 SQL 根和真实 ACK Broker；AI 入站为受控签名夹具、observer只ACK，不表示完整 AI producer、进程退出、数据库提交网络故障、system 或生产验收。必需结果和失败历史回链 infra 唯一执行总表；没有通过门禁不勾选 T15。
