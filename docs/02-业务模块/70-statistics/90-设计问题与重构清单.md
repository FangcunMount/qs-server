# Statistics 设计问题与后续优化清单

> 状态：当前保护、剩余风险与验收责任。历史环境演练、首次发布和阶段性数据量不证明当前 checkout 的 migration、部署或统计水位；版本判定见[版本台账](../../00-总览/09-当前版本定档验收台账.md)。

## 1. 当前结论

四类 Collector、四张 Fact、五张 Daily、Organization Snapshot 和 SyncRun 已在生产组合根装配。
Survey 独立开始事实、Collection/gRPC 可选引用、Mongo 唯一提交、Journey 开展上下文、StoreActivity Fact/Daily 与运营查询均已有代码/迁移。
医生自助 `/statistics/clinicians/me` 及子路径已退役返回410，原 ST-010 可达入口风险不再作为当前开放缺口。
这不意味着新迁移、权限、统计 publish、旧端兼容或真实门店业务场景已经在当前生产验收。

## 3. ST-001：Migration 完整演练

当前事实入口包括 `internal/pkg/migration/migrations/mysql/000080_answering_start.up.sql` 和 `000082_statistics_store_activity.up.sql`。
分别验证升级、空库构建和结构回退；回退结构不表示恢复已经清理的统计数据。Migration 文件存在、contract test 和真实环境演练属于不同证据。

## 4. ST-002：冷启动链路

最小 Actor/Store/Testee、AnsweringStart、AnswerSheet、Assessment/Outcome、PlanEnrollment/Task 建立后，执行 validate/repair/publish，
从来源→Fact→Daily/Snapshot→ReadService/API 核对。相同窗口重跑不得增加相同业务事实或漂移总数，未知开始必须保留原因。

## 5. ST-003：发布与 freshness

每个启用机构单独核对当前 Run、窗口、Collector/Projection 计数、Snapshot、Generation、as_of_date/snapshot_at。
没有完整发布就保持 not_ready，空 publish 可建立水位但不得伪造业务量。历史大数据量与服务健康不能替代当前统计发布验收。

## 6. ST-004：采集数据库级证据

新来源继续验证半开窗口、稳定身份、跨页无遗漏/重复、迟到 repair、核心冲突失败和 validate 不写。
StoreActivity 的 Mongo cursor 与 MySQL keyset 分别核对执行计划、索引与未知上下文；不能从其它三类来源测试推定新增来源性能。

## 7. ST-005：当前资源与历史开展

Actor 当前服务人数与冻结开展量是不同观察。转店影响当前访问/资源范围，不改写已冻结开展门店。
NULL/0 技术桶不是公司范围，指定门店不得混入公司未知桶；无开始的旧数据不按当前门店回填。
口径由[统计指标](./40-统计指标与口径.md)维护，不在本台账复制另一套分母。

## 8. ST-006：容量触发

保留全机构 Fulfillment 的最简单重建方案，按实际规模记录耗时、锁时长、存储增长与查询成本。
只有越过明确容量阈值才设计增量化，不恢复 Checkpoint/Pending 双轨。

## 9. ST-007：失败停点

结果事务失败保持旧发布；数据已提交、缓存发布失败保持 data_committed，resume-cache 仅续传缓存与水位，不重采集/投影。
要求故障注入覆盖重复续传、进程退出和 Redis 恢复；接口200和一条日志不能证明水位闭环。

## 10. ST-008：保留周期

保留政策由真实增长率、历史业务查询与恢复责任决定。删除或归档计划单独审核，不能因重建方便而删除权威业务事实。

## 11. ST-009：Task 重排履约

按 Enrollment 和 schedule_revision 定义 planned/due cohort，活动次数与重排履约分开。
当前数据是否无 legacy fallback 必须重新对账；过去固定Task数量不作为当前代码/生产完成证据。

## 12. ST-010：已退役的医生自助入口

`internal/apiserver/transport/rest/routes_statistics.go` 将 `/statistics/clinicians/me` 与全部子路径注册到 retiredClinicianAPI，返回410，不读取统计业务数据。
原 inactive clinician self overview SQL 风险不再经该 HTTP 入口可达。以后若新建医生自助产品，需重新设计身份/动作/当前资格与缓存授权，不能恢复旧 handler 作为默认方案。

## 13. 当前验收门槛

源码与 machine contract 对齐、普通回归、真实数据库专项、CI、当前部署/config、统计发布/对账、真实角色/客户端验收分别记录。
新迁移/权限、Scope、未知桶、跨月归属、缓存覆盖与转店竞争未验证时，状态保持待补证据；文档或门禁通过不提升生产状态。

## 15. ST-011：作答开始记录、开展门店与客户端兼容

### 15.1 当前责任链

Actor 拥有当前服务门店与归属版本，Survey 拥有开始记录、开始意图及提交资格，Evaluation 保存开展上下文，Statistics 派生历史开展 Fact/Daily。
开始与转店共享 Testee 锁；同 request key 同输入返回原时间/门店，异输入冲突。提交校验原开始身份/内容，当前关系与入口资格仍有效才受理；旧开始不赋予永久权限。
一开始只对应一份耐久答卷，后续重放复用该身份，不制造额外计数。

### 15.2 当前实现与兼容

已装配 AnsweringStart 与提交 resolver；迁移000080保存开始记录，000082保存开展 Fact/Daily。
新提交沿 AnswerSheet→Journey→Assessment 传递冻结上下文；历史/旧端没有开始引用时明确 legacy_start_not_captured，开始时无门店为 unassigned_at_start。
当前门店后来变化不回填旧开展；公司未知桶只用于明确的统计口径，不赋予访问权。
业务开始/提交合同见[Survey](../10-survey/README.md)，Fact/粒度见[领域模型](./10-领域模型.md)与[数据分层](./20-核心设计-业务数据、事实与统计分层.md)。

### 15.3 剩余验收

当前部署与迁移、新旧客户端比例、开始覆盖与未知原因、提交丢响应、重复消费、首次成功计数、跨月归属、转店竞争和真实总部/门店角色场景分别取证。
统计 publish 与业务验收未绑定当前版本时保持待补证据，不把已实现接线写成规划未实施，也不把本地实现写成生产已上线。
