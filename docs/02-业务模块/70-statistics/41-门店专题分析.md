# 门店专题分析

## 目标与访问边界

统计中心将服务概览、临床人员、计划执行合并到门店分析。共享 `qs:statistics:collection:operations / read` 和当前 Operator 的公司、门店 Scope；无需增加 IAM Grant、Assignment 或 Scope。运营员、计划管理员、结果评估员可使用纯统计；内容管理员不因本次改造获得统计权限。报告、答卷、管理、重试与旧专业统计接口继续执行原权限检查。

## 四个专题的口径

| 专题 | 归属与计量 |
| --- | --- |
| 服务概览 | 当前门店受试者的累计服务、查询期间事件；医生及入口规模按医生当前门店 |
| 临床人员 | 仅当前关联所选门店的医生，关系人数和服务事件同时过滤受试者当前归属 |
| 计划执行 | 当前门店受试者的任务事件与履约；复用原任务版本、取消、到期与完成公式 |
| 历史开展 | 开始作答冻结门店；提交与首次成功分别计数，未知桶仅公司全部门店可见 |

转店后历史服务和计划情况随当前归属交接，历史开展量不变。医生调店而受试者留原店时，原店不再列该医生，但受试者服务事实仍归原店。多医生关系人数可能重叠，医生行不能相加作为独立人数或完整服务量。

未识别人身份的入口打开事件按入口当前医生门店；不能与接入人数相除作为转化率。未归属受试者不进入前三个专题。人工随机初配仅影响当前归属分析，不回填历史开展门店。

## 查询合同

新增 GET `/api/v2/statistics/operations/analysis/` 下的 `overview`、`clinicians`、`entries`。统一 `from`、`to`（上海日期左闭右开）、`store_ids`（逗号分隔字符串 ID）；默认本月，最大跨度复用运营统计限制366天。分页默认20，最多100；入口可按 `clinician_id`、`is_active` 筛选。

概览同时提供服务与计划数据，相同筛选下共用一次请求。医生返回全范围 summary 与当前页 items；入口只返回安全展示字段及计数，不返回 Token、扫码地址、评分、风险、报告正文或内部异常。生成的 OpenAPI 是字段合同来源。

响应包含生效门店、请求日期、`data_through`、`published_version`、`published_at` 和 `current_ownership_read_at`。当前人数与已发布事件截止时间分别展示；覆盖不足或未发布返回不可用，不伪造零值。

## 分层及一致性

HTTP 解析参数；ReadService 校验有效 Operator、公司、动作和门店子集；MySQL 在聚合、计数和分页前过滤范围。指定不可见门店或医生拒绝。ScopedOverview、ScopedClinicians、ScopedEntries 复用现有计算，医生全范围汇总与分页在同一只读重复读事务中完成。

当前归属专题不进入公司缓存。沿用数据库并发限制、查询超时和返回前发布版本复核。历史开展保持既有发布缓存。没有新增事实、数据库结构或统计重建任务。

## 验证与发布

自动化包含动作权限隔离、无 Operator、跨公司和越权筛选、无发布覆盖、字符串 ID、入口白名单、全范围汇总与分页、医生调店。隔离 MySQL 专项为 `TestScopedOverviewMySQL`、`TestScopedClinicianAnalysisMySQL`；CI 必须设置 `QS_SCOPE_MYSQL_DSN` 及 `QS_SCOPE_MYSQL_REQUIRED=1`，缺失失败。

先发布 QS 并验证新接口，再发布运营端。旧专业接口保持兼容。回退优先恢复上一运营端版本，新接口可保留；禁止放宽旧接口门禁。无需 IAM 发布、生产赋权、人员重新分配或全量统计重建。

代码检查、部署 SHA、总部与普通门店 API 正反场景、界面确认分别留证。本地测试不能代替线上验收。
