# 宣讲

宣讲层把已复核的工程事实压缩成可阅读、可讲述、可追溯的技术材料，不承担实现真值，也不代替运行或生产证据。

## 1. 当前材料

- [系统技术简报](./01-系统技术简报.md)：提供 3/10/30 分钟阅读路线，以及架构、可靠受理、评估/解释边界、容量判断和 Mongo 一致性审计五张案例卡。
- 需要先建立整体地图时，回到 [系统地图](../00-总览/03-系统地图.md)、[三进程协作总览](../01-运行时/00-三进程协作总览.md)和 [源码事实矩阵](../00-总览/07-源码事实矩阵.md)。

## 2. 派生规则

- 所有重要结论必须回链 `docs/00-总览` 至 `docs/05-决策记录`、机器契约或真实源码；
- 代码事实、历史运行证据、当前生产证据和规划必须分开标记；
- 案例卡固定使用“问题—约束—备选方案—决策—代码链—失败窗口—验证—仍存边界”，不只列技术组件；
- 个人角色、实际贡献、协作冲突和个人量化结果不属于仓库事实，必须由陈述者本人填写，不得从源码、提交记录或历史对话推断；
- 规划内容必须标“规划改造”，旧宣讲快照不可直接复制回现行层。

## 3. 更新方式

真源发生变化时，先修正所属模块、运行时或运维文档，再重新派生本目录的短答、路线和案例卡。不允许只修改宣讲口径来掩盖实现或证据漂移。
