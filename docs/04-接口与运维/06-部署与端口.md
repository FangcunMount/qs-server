# 部署与端口验收 Runbook

## 1. 前置条件

只对已批准的 exact SHA、镜像 digest 和部署计划执行。镜像/CD/网络事实见[镜像、CD 与网络拓扑](../03-基础设施/config-deployment/20-镜像、CD与网络拓扑.md)，
验收与回滚边界见[部署验收与回滚](../03-基础设施/config-deployment/30-部署验收与回滚.md)，管理端点的安全边界见[敏感信息、网络暴露与验收](../03-基础设施/security/20-敏感信息、网络暴露与验收.md)。

发布前准备：

- source SHA、三个镜像 digest、服务计划与部署顺序；
- 脱敏 effective-config hash、migration 兼容结论与回滚镜像；
- 允许源 → listener/path 矩阵，以及至少一个禁止源；
- 逐实例而非只经负载均衡的 probe 地址；
- 观察窗口、owner、停止阈值和证据目录。

## 2. 仓库与部署包预检

```bash
git rev-parse HEAD
make docs-check
bash scripts/cd/test-plan-services.sh
bash scripts/cd/test-prepare-package.sh
bash scripts/cd/test-production-compose-network-exposure.sh
bash scripts/cd/test-wait-worker-readiness.sh
bash scripts/cd/test-verify-worker-governance.sh

for service in apiserver collection worker; do
  make cd-validate SERVICE="$service"
done
```

任何测试失败、source SHA 不一致、镜像 fallback 到 `latest`、migration 未确认或回滚兼容不明时停止发布。

## 3. 目标环境展开与 listener 盘点

```bash
export COMPOSE_FILE='/path/to/docker-compose.prod.yml'
export COMPOSE_ENV_FILE='/path/to/config.prod.env'
umask 077
export COMPOSE_RENDERED="$(mktemp)"
trap 'rm -f "$COMPOSE_RENDERED"' EXIT

docker compose --env-file "$COMPOSE_ENV_FILE" -f "$COMPOSE_FILE" config >"$COMPOSE_RENDERED"
shasum -a 256 "$COMPOSE_RENDERED"
docker compose --env-file "$COMPOSE_ENV_FILE" -f "$COMPOSE_FILE" ps
docker compose --env-file "$COMPOSE_ENV_FILE" -f "$COMPOSE_FILE" images
```

再对每个容器保存实际 host mapping、network membership 和进程 listener：

```bash
docker inspect "$CONTAINER_ID" --format '{{json .NetworkSettings.Ports}}'
docker inspect "$CONTAINER_ID" --format '{{json .NetworkSettings.Networks}}'
docker exec "$CONTAINER_ID" sh -c 'ss -lntp 2>/dev/null || netstat -lnt 2>/dev/null'
```

若镜像没有 `ss/netstat`，从宿主机或具备授权的诊断容器采集等价证据，不为排障把工具永久装入生产镜像。

## 4. 正向网络与逐实例 probe

从批准的入口、Prometheus/CD runner 和服务调用方分别验证业务 HTTP、gRPC health、metrics/governance。
probe 的实际含义与路径见[健康探针 canonical 文档](../03-基础设施/observability/20-健康探针、治理与持久证据.md)。

```bash
curl --fail-with-body --silent --show-error --max-time 5 "$INSTANCE_HEALTH_URL"
curl --fail-with-body --silent --show-error --max-time 5 "$INSTANCE_READY_URL"
grpcurl -cacert "$GRPC_CA_FILE" -cert "$GRPC_CERT_FILE" -key "$GRPC_KEY_FILE" \
  "$GRPC_TARGET" grpc.health.v1.Health/Check
```

每个实例都要命中一次并记录容器/镜像身份。一个负载均衡 200、容器 `running` 或 gRPC 101/health 响应不能替代业务、依赖和资源授权检查。

部署钩子还运行 `scripts/cd/runtime-evidence.py`，按本次 CD run／attempt、完整 source SHA 和 frozen 副本数逐实例采集。API 使用 `qs-apiserver`，Collection 使用 Compose project `qs-collection`／service `server`，Worker 使用 `qs-worker`／`runtime`；停止的残留实例也参与数量检查。观察器在采集前后重读完整实例集合与状态，核对固定二进制和 `/proc/1/exe` 的 SHA256、二进制实际 GitCommit、固定 readiness；重启、替换或多余实例拒绝出具成功回执。
逐实例核验沿用宿主已选择的 Docker 权限方式：配置了 `SUDO_PASSWORD` 时，仅将密码经标准输入交给固定的只读 Docker 命令；未配置时使用非交互 sudo。核验 Python 保持普通部署账号运行，密码不进入命令参数或回执。
镜像引用分两条已绑定路径：普通部署核对完整 source SHA 标签；API 的 AI MQ 不可变发布路径只接受预检后已核对的完整镜像 config ID，容器 `.Image` 与 `.Config.Image` 必须同时精确匹配。固定 ID 参数由部署脚本在核验成功后传给观察器，不能由工作流输入替代；编译 SHA、程序哈希和 readiness 仍分别核对。版本 2 回执记录 `image_binding_kind` 与可空的预期 config 摘要，接收端校验来源／run／attempt、工具摘要、实例及绑定关系；正文摘要仅检验回执字节完整性。实际现场来源与新鲜度由对应运行证据另行绑定，回执不签署业务验收。

回执中的 `image_config_sha256` 是 Docker 实际运行镜像的内容标识，不冒充 registry manifest digest；预置制品仍须另行绑定批准的构建／发布摘要。版本命令只使用固定配置路径，原输出在内存丢弃，不读取或输出 inspect.Env。Python 以部署用户运行，仅固定的只读 Docker executor 可选择 `sudo -n docker`；权限或探针失败保持失败，不升级权限。`health_verified` 与 `business_acceptance_verified` 分开，观察器不会签署业务验收。

## 5. 反向网络验收

从宿主公网、未授权容器网络或其它禁止源执行：

```bash
if curl --fail --silent --show-error --max-time 3 "$FORBIDDEN_MANAGEMENT_URL"; then
  echo 'FAIL: management endpoint is reachable from a forbidden source' >&2
  exit 1
fi
```

重点确认 worker management listener `0.0.0.0:9092` 没有被宿主公网 publish；它同时承载 metrics、health/readiness 和 governance，且没有业务 API 身份认证。
Compose `expose: 9092` 只声明容器网络可见性，不是访问控制。还要反向验证 profile/governance、内部 gRPC 和未授权 Nginx 路径不可达。

网络 ACL 与 gRPC default-deny 方法 ACL 是两层证据：必须同时做“允许来源成功”和“禁止来源失败”，任一层都不能替代另一层。

## 6. 失败处置、回滚与完成标准

- digest/SHA 不一致：停止并恢复到未接流量状态，禁止给错误镜像补标签；
- listener 或 host mapping 超出矩阵：先隔离网络，再修 Compose/防火墙/Nginx；
- readiness 失败：不要强制接流量；按依赖、control sync、Redis runtime 和启动阶段排查；
- migration 已执行且旧程序不兼容：停止自动回滚，进入[Migration 与恢复](../03-基础设施/migration-recovery/README.md)；
- one-off 已写数据：按该工具备份/复验方案恢复，不能用镜像回滚假装撤销数据。

完成记录包括 source/deployed SHA、镜像 digest、effective-config hash、展开配置 hash、listener/network、逐实例 probe、正反向访问、观察窗口与限制；
真实结果只写入[基础设施生产证据台账](../00-总览/10-基础设施生产证据台账.md)。
