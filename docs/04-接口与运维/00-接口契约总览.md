# 接口契约核验 Runbook

## 1. 适用场景与事实源

新增、删除或修改 REST、gRPC、Event、Signal、错误响应或安全声明时执行本流程。机器事实源是：

- REST：[`api/rest/apiserver.yaml`](../../api/rest/apiserver.yaml)、[`api/rest/collection.yaml`](../../api/rest/collection.yaml)；
- gRPC：[`api/grpc/proto`](../../api/grpc/proto/)；
- Event / Signal：[`configs/events.yaml`](../../configs/events.yaml)、[`configs/signals.yaml`](../../configs/signals.yaml)。

Event/Signal 的传播语义见 [Event canonical 文档](../03-基础设施/event/README.md)，安全语义见 [Security canonical 文档](../03-基础设施/security/README.md)。本页不维护字段或端点枚举。

## 2. 前置检查

```bash
git rev-parse HEAD
git status --short
go version
python3 -c 'import yaml; print("PyYAML OK")'
command -v swag
```

若 `swag` 缺失，按 Makefile 锁定版本安装；若工作区已有无关改动，先记录并在后续 diff 中排除，不能覆盖。

## 3. 生成并对比

```bash
make docs-check
make docs-api-verify
git diff --check
git diff -- api/rest internal/apiserver/docs internal/collection-server/docs api/grpc/proto api/grpc/gen configs/events.yaml configs/signals.yaml
```

预期结果：

- `docs-check` 与 `docs-api-verify` 退出码为 0；
- 生成后只出现本次预期的契约差异；
- OpenAPI 的 path/method、operationId、路径参数、安全声明和标准错误响应比较通过；
- 没有“只改 prose、未改机器契约”或“只改生成物、未改生成源”的差异。

失败时先保留生成 diff，再回到 handler/注解、proto 或 YAML catalog 修正；不要手改生成文件来消除漂移。

## 4. 按变更类型追加定向测试

```bash
# REST
go test -count=1 ./internal/apiserver/transport/rest/... ./internal/collection-server/transport/rest/...

# gRPC server/client/ACL
go test -count=1 ./internal/apiserver/transport/grpc/... ./internal/collection-server/infra/grpcclient/... ./internal/worker/infra/grpcclient/...

# Event / Signal
go test -count=1 ./internal/pkg/eventing/... ./internal/apiserver/application/eventing ./internal/worker/integration/eventing ./internal/pkg/signalcatalog ./internal/pkg/architecture
```

只运行受影响组即可，但记录中必须说明为何其它组不适用。测试通过不替代真实调用方兼容或环境网络验证。

## 5. 接入验收与退出条件

1. 用当前机器契约重新生成客户端或适配层；
2. 对新增/修改接口执行一个成功请求、一个认证/授权拒绝请求和一个业务校验失败请求；
3. 对 Event/Signal 变更验证 producer、catalog/registry、consumer 和恢复语义；
4. 保存 checkout SHA、命令、结果、调用样例和已知限制；
5. 若存在不兼容字段号、路径、枚举、身份或资源归属变化，停止发布并先完成兼容方案。

真实环境或生产结果只写入[基础设施生产证据台账](../00-总览/10-基础设施生产证据台账.md)。
