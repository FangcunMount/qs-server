# 架构决策总表

## 1. 三进程但单一业务事实中心

结论：collection 承接前台保护，worker 驱动异步任务，apiserver 持有业务状态机与持久化。

约束：collection/worker 不直接写主业务 repository。证据见 [系统地图](../00-总览/03-系统地图.md) 与三个进程入口。

重新评估条件：某个边界进程开始独立拥有数据、事务和业务生命周期。

## 2. 同步保存答卷，异步执行评估与报告

结论：collection 只有在 Mongo transaction 已提交 `AnswerSheet + (writer_id, idempotency_key) 幂等事实 + answersheet.submitted Outbox` 后才返回 `202 Accepted`；Assessment、Evaluation 和 Interpretation 由 Worker 与可靠事件异步推进。

约束：

- 相同 writer/idempotency key 与相同 fingerprint 读回同一持久结果；相同 key、不同 fingerprint 必须冲突；
- Mongo commit 结果未知时，只能在脱离原请求取消的短时只读回查确认命中后承认成功；
- `DurableSubmitCoalescer` 只是可关闭的同进程效率层，不能承担正确性或持久化；
- Worker 消费 `answersheet.submitted` 是正常创建或恢复 Assessment 的唯一入口；
- 客户端必须处理 accepted/processing/final 等状态，不能把提交成功等同于报告完成。

实现与失败窗口以 [答卷校验与可靠受理](../02-业务模块/10-survey/31-关键链路-答卷校验与可靠受理.md)和[可靠提交、跨实例合并与幂等](../03-基础设施/concurrency/30-可靠提交-跨实例合并与幂等.md)为 canonical；事件契约以 `configs/events.yaml` 为准。

重新评估条件：业务需要同步强一致返回评估结果，且容量与失败语义允许。

## 3. 可编辑模型与运行时发布快照分离

结论：草稿用于 authoring，已发布快照用于运行时；运行链不能读取可变草稿。

约束：发布、重复发布、从已发布版本派生新草稿和绑定都必须保持显式状态语义。证据见 [ModelCatalog](../02-业务模块/20-model-catalog/README.md)。

重新评估条件：能用同一物理存储结构证明不可变版本、原子发布和运行隔离，且迁移收益明确。

## 4. Evaluation 与 Interpretation 分离

结论：Evaluation 提交机制中立 Outcome；Interpretation 独立生成、重试、存储和查询报告。

约束：Interpretation 只读 Outcome，不推进 Evaluation 状态；Evaluation 不拥有报告成品。证据见两个模块的 `domain/doc.go` 与 canonical 文档。

重新评估条件：报告完全退化为无状态同步格式化，且不再需要独立重试、持久化和查询生命周期。

## 5. Outbox、MQ、Signal 分工

结论：Outbox 保证可靠出站，MQ 负责异步传输/消费，Redis signal 只做临时唤醒。

约束：signal 丢失必须可由查询、TTL 或重试兜底；可靠业务事实不得只发 Pub/Sub。证据见 [Event](../03-基础设施/event/README.md)、`configs/events.yaml` 和 `configs/signals.yaml`。

重新评估条件：底层传输提供不同但同等可证明的投递与恢复语义。

## 6. Statistics 作为可恢复读侧

结论：统计通过投影、扫描、checkpoint 与 reconcile 构建，允许明确的最终一致性。

约束：读侧不能反向拥有主业务事实；可重建也不代表存储可直接删除。证据见 [Statistics](../02-业务模块/70-statistics/README.md)。

重新评估条件：查询可以直接从主事实高效、稳定生成且不再需要独立口径和缓存。

## 7. seeddata 历史能力永久退役

状态：已接受并实施。日期：2026-08-02。代码、MySQL 64 与 MongoDB 20 必须在同一维护窗口切换。

结论：qs-server 永久下线 seeddata 批量历史数据、业务时间注入、批次/场景进度、断点续跑、
回放和回滚控制面，只处理当前时间下的正常业务请求和每日 mock 数据。普通 Actor、
Assessment Entry、Plan、AnswerSheet、Evaluation、Interpretation、可靠提交、幂等、Outbox、
readiness、重试治理、租约和报告等待语义保持不变。

接口约束：apiserver 与 collection 在读取请求体之前拒绝任意出现（包括空值）的
`X-QS-Historical-Context`、`X-QS-Historical-Requested-At` 或
`X-QS-Historical-Signature`，固定返回 HTTP 403。historical-seed stage REST 路由及 OpenAPI
定义已删除，访问返回路由级 404。公共 Proto 的 `historical_context` 字段已删除，原字段号和
字段名同时 `reserved`；公共 `HistoricalExecutionContext` Proto 及生成代码已删除。

seeddata-runner 不得发送历史 Header、持有历史签名密钥、调用 stage API，或提供 batch、
scenario、timeline、resume、manifest verify 与历史回放。每日 mock 只能通过普通 Testee、Entry、
Model、Questionnaire、Plan、AnswerSheet、readiness 和 report-wait 接口使用当前日期执行。

数据约束：MySQL `000064_retire_seed_backfill_control` 按依赖顺序删除
`seed_backfill_rollback_phase_attempt`、`seed_backfill_rollback_resource`、
`seed_backfill_rollback_operation`、`seed_backfill_stage_attempt`、`seed_backfill_stage`。
MongoDB `000020_retire_legacy_collections` 删除 `published_assessment_models`、
`interpret_reports`、`evaluation_rule_sets`、`scales`。两套 Down 只重建空结构和旧索引，不恢复
数据；生产回退必须成对完整恢复 MySQL 与 MongoDB（包括 migration state）。

兼容约束：`assessment_task.business_created_at` 及迁移历史保留。已重建任务继续通过
`COALESCE(business_created_at, created_at)` 影响 Statistics 日期；新任务保持该字段为 `NULL` 并
回退到 `created_at`。旧事件 JSON 中多余的 `historical_context` 字段作为未知字段忽略。

发布约束：预发布至少提前 24 小时关闭旧能力、恢复 Plan scheduler 并观察一个完整每日 mock
周期。主发布必须全量停机，确认没有活动批次、运行中回滚或携带历史上下文的待处理 Outbox，
完成两库全量备份、SHA-256、对象计数和临时库恢复演练。只允许从 MySQL 63、MongoDB 19 且
五张表、四个集合均存在的状态迁移。隔离启动单个 apiserver 迁移和验证后，才能启动其余组件
并执行当前时间闭环 smoke；禁止滚动发布、新旧版本混跑和带流量迁移。

回退约束：任一前置检查、备份、迁移、索引、健康检查或 smoke 失败，必须保持入口阻断，停止
新版本，成对恢复两库到 MySQL 63、MongoDB 19，再部署上一版本；历史能力仍保持禁用。

验收证据：发布包必须包含预发布 24 小时与每日 mock 记录、批次/rollback/Outbox 前置查询、
两库备份标识与校验和及计数和恢复演练、迁移版本与删除对象及 canonical indexes 验证、全部
自动化门禁、当前时间 Testee → Plan → AnswerSheet → Assessment → Evaluation → Report 闭环，
以及发布后一个完整每日 mock 周期结果。仓库 `runtime-closure-e2e` 使用 MySQL 8.4、MongoDB 7
Replica Set 和 Redis 验证当前时间闭环、冷启动迁移、幂等、readiness、Outbox 与新任务时间语义。

重新评估条件：无。该协议字段和 Proto 编号均已保留，不允许恢复或复用。
