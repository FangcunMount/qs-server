# 敏感信息、网络暴露与验收

## 1. 当前结论

qs-server 的部分管理端点没有应用层认证：worker 9092 暴露 metrics/health/ready，apiserver 与 collection 的 `/metrics`、profile 或 governance 端点也依赖入口路由和网络边界。仓库内绑定地址或 Compose `expose` 只能描述意图，不能证明公网不可达。

本页负责 Secret、日志内容、管理端点与网络正反向验收；资源 ownership 仍以[身份、服务与资源授权](./10-身份、服务与资源授权.md)为准。

## 2. 暴露面矩阵

| 进程/端点 | 代码/配置事实 | 安全含义 |
| --- | --- | --- |
| apiserver HTTP `/healthz`、`/readyz`、`/metrics`、governance | HTTP server 按配置启用，生产 bind 为 `0.0.0.0`; host port 由 Compose 回环映射/Nginx 管理 | endpoint 本身的响应语义与网络可达性分开；不得从回环 mapping 推断所有 overlay 路径都安全 |
| apiserver gRPC 9090 | production YAML 声明 mTLS + ACL default deny；标准 gRPC health 与业务服务同端口 | 必须验证未知证书、错误 OU、未授权方法和无委托主体请求均失败 |
| `grpc.healthz-port: 9091` | 配置字段存在，但当前 `internal/pkg/grpc` 未据此创建独立 HTTP listener | 不得配置 9091 成功探针；环境验收应确认它没有 listener，若出现监听即视为实现/配置漂移 |
| collection 8080 / 6060 | 8080 在 Docker 网络 expose；profiling server 绑定 `127.0.0.1:6060` 的进程语义需结合容器网络理解 | Nginx 只放行业务/授权观测路径；profile 不得直接公网暴露 |
| worker 9092 | `metrics.bind_address: 0.0.0.0`；handler 提供 `/metrics`、`/healthz`、`/readyz` 且无应用认证 | 必须由 overlay/主机防火墙/Nginx ACL 或专用采集网络限制；同时做允许采集与拒绝公网的双向测试 |

## 3. 敏感信息

禁止进入日志/指标 label/文档证据：token、cookie、Authorization、数据库/Redis 密码、TLS 私钥、委托签名 key、答案正文、报告正文、可枚举个人资源 ID 与原始 error 字符串。

当前需要保持的风险：

- collection `APILogger` 可记录最多 16 KiB request/response body，字段名脱敏无法覆盖所有医疗/测评内容；
- request ID 可由调用方提供，未做格式/长度约束，只能用于关联，不能作为可信身份；
- Prometheus label 必须是有限枚举。已存在的 `org_id` 或原始错误 label 使用需视为待治理 gap，而不是把规范改写成“当前已全部满足”；
- Debug/profile/metrics 开关必须从 effective config 验证，不能只看 repository YAML。

## 4. 网络验收

每个环境至少执行并保存：

1. 监听器清单：进程内 `ss/lsof`、容器 port/expose 和 host mapping；
2. 入口配置：Nginx/ingress 展开后的配置哈希与允许路径；
3. 正向：Prometheus/部署 runner 能读取批准的探针，业务客户端能完成允许的 mTLS/RPC；
4. 反向：确认 9091 没有 listener；公网/非授权网段访问 9092、6060、governance、pprof 和内部 gRPC 均失败；
5. 身份反向：错误 CA/OU/CN、无证书、无 delegated subject、未列入 ACL 的方法均失败；
6. 资源反向：跨用户、跨机构、inactive ProfileLink/Testee relationship 均 fail closed。

只做正向 200 不构成安全验收；只做端口扫描也不能证明资源 ownership。

## 5. 非缓存测试与证据边界

```bash
go test -count=1 ./internal/pkg/grpc ./internal/pkg/configcontract ./internal/worker/observability
bash scripts/cd/test-production-compose-network-exposure.sh
```

这些命令证明当前 checkout 的 loader、ACL 规则、handler 和 Compose ratchet。真实监听、主机防火墙、Nginx effective config、TLS 证书链和跨用户行为必须单列环境/生产证据。

## 6. 未闭合 gap

- 两条 Actor ownership P0 使 Security 当前 blocked。
- worker 9092 的网络保护缺少与当前 checkout 绑定的生产反向证据。
- `grpc.healthz-port` 配置与实现 listener 不一致，需删除误导配置或补实现与测试。
- collection body logging、raw error/org label 仍有隐私与基数风险。
- 当前 checkout 没有脱敏 effective-config hash、证书有效期和 Secret rotation 证据。
