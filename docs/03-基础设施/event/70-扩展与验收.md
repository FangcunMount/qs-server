# Event / Signal 扩展与验收

新增消息先明确业务责任和丢失损失，再选择传播机制。通用 Appender/Store/Relay/NSQ API 使用[当前依赖版本的 SDK 合同](./10-架构与责任边界.md#sdk-版本与参考文档)；本页只列 QS 需要同步的契约与证据。

## 新增 Event

1. 明确发生的事实、业务 owner、aggregate、组织范围与稳定事件身份。不可丢的流程用 durable_outbox，可丢业务通知用 best_effort；缓存/等待者回读提示用 Signal。
2. 在 QS 定义 DomainEvent 与业务 payload DTO。envelope/历史 wire 使用 SDK wire/domain、wire/legacy；不要新增本地通用 codec 或恢复 component-base 消息依赖。用 JSON 表征固定业务字段和兼容语义。
3. 同步 configs/events.yaml、EventSpec、显式 handler registry 和[唯一事件矩阵](./20-事件契约与演进.md)。记录幂等、settlement 与需要的独立 consumer/channel。
4. Durable producer 按业务数据库选择标准 Profile，在原 Mongo/MySQL 事务调用 Stager；提交成功后每批调用一次 PostCommit。Rollback 不唤醒，缺事务失败，不构造第二个 writer。原消息 ID/bytes 跨技术重试保持不变。
5. Best-effort producer 使用 RoutingPublisher，明确错误是返回还是记录；logging/nop 不具有持久化保证，不能承载关键事实。
6. Consumer 在 ACK 前完成当前事件声明的持久边界，或转交 durable hold。未分类依赖/持久化错误返回原 error。Worker unknown 须持久审计成功后 ACK；附加投影过滤另有合同。
7. 围绕副作用选择原业务唯一键、run claim、CAS、稳定回执或专属账本；外部结果未知先核对，不借物理重投许可重新执行业务。
8. 同一事实的独立投影用 AdditionalConsumers 和稳定独立 channel，在 Start 前绑定；不要在 publisher hook 执行业务投影。同步配置、status、指标与失败隔离测试。
9. 若要求 published 后效果恢复，定义宿主 scanner、原身份核验和授权责任；不能假设 SDK pending 扫描能发现已确认效果缺口。

`immediate/priority` 当前是兼容字段，须与矩阵同步，但不驱动旧 immediate/priority-tier 执行器。不要为了一个新事件重建 ready-index、reconciler 或独立协议栈。

## 新增 Signal

1. 确认消息只提示刷新，丢失后有 TTL、下次变更或权威查询兜底。
2. 同步 configs/signals.yaml、signalcatalog 常量及 transport-agnostic SignalName/SignalKey/payload。
3. 在所属 CacheSubsystem 或 report-status runtime 绑定 SDK Redis notifier/watcher，保留 borrowed-client 与 Start/Close 所有权。
4. disabled 不创建订阅/发送；通知错误不推翻已提交事实。
5. 同步[Signal 拓扑](./60-Signal一次性信令.md)，核对实际 publisher、watcher 和重连/回读，不仅比较两个硬编码清单。

如果需求要求持久必达、ACK 或人工重放，应重新判断是否需要 durable Event。

## 改变已有契约

| 变更 | QS 必须处理 |
| --- | --- |
| payload 可选新增 | DTO/JSON 测试与旧 consumer 容忍 |
| 字段/事件语义破坏 | 新版本/新事件、兼容窗口及原消息身份 |
| topic/channel/provider | 节点与 channel 准备、积压/失败中转、双运行或回退责任 |
| best-effort 升 durable | 原事务 staging、Profile、业务效果及未知外部调用规则 |
| ACK/handler error | Worker/投影政策、持久审计/hold、outcome 与回归 |
| SDK/schema 升级 | go.mod、原事务/claim/时钟/wire、显式迁移及历史数据回退限制 |
| 删除事件 | 全部 producer、原 Outbox、所有 channel 与旧部署退出证据 |

## 必须验证的窗口

- 原事务共同 commit/rollback；没有活动事务不能暂存，Mongo callback 重入保留原意图。
- Wake 丢失/进程退出后的 SDK 周期发现；claim lease 到期、迟到写回与发送结果 Unknown。
- PUB 确认不提前记 published；Store.Confirm 失败保留原错误，观测标签来自真实消息，scan 失败不发明事件标签。
- decode/handler 错误进入 SDK NACK；Worker unknown 审计失败不能 ACK；hold 持久成功后才 ACK。
- 业务 handler 预算耗尽、中转确认与 MySQL recorder 分别失败时仍保留各自恢复责任；应用 UUID 与物理 ID 分开。
- 每种副作用重复处理等价，未知外部调用不获盲重发许可；独立投影失败不阻断主 channel。
- published 效果缺口扫描、原冻结事实/身份/bytes 核验及治理授权；scanner 本身不发消息。
- 启动失败清理、Run 取消后等待已接纳发送/结算，drain 后关闭真实专用 Producer，借用数据库由宿主关闭。
- replay 组织/attempt/占用冲突、最佳努力限制、未知结果不换编号试探；报告结案审计与死信同事务。

原事务/效果 scanner/真实 Broker 测试有各自 build tag 和隔离依赖，普通包测试不包含所有窗口。先阅读具体测试的环境前提，不使用生产库或正式消息验证文档改动。

| 实库/故障合同 | 当前入口 |
| --- | --- |
| SDK 原 Mongo/MySQL 事务、GORM、迟到 claim、Broker 故障 | [当前依赖 tag 的 tests/integration](https://github.com/FangcunMount/reliable-messaging/tree/v0.3.0-mq-ai.2/tests/integration) 与脚本 |
| QS 原事务与标准 Evaluation/Interpretation 流 | internal/apiserver/container/internal/transaction 的集成测试 |

| 标准 retry 政策与 status/replay | internal/apiserver/eventing/standardoutbox、infra/{mongo,mysql}/standardoutbox 的集成测试 |
