# 镜像、CD 与网络拓扑

## 1. 当前结论

仓库为 qs-apiserver、collection-server、qs-worker 分别构建镜像，通过同一生产 Compose 模板按服务计划部署。Compose 定义的是期望拓扑；主机归属、副本数和当前运行镜像必须由某次 exact-SHA 部署证据确认。

本页是 `deployment/CD/network` 主题的 canonical 文档。

## 2. 交付链

```text
Git SHA
  -> build/docker/Dockerfile.<service>
  -> image metadata / registry or exported archive
  -> scripts/cd/prepare-package.sh
  -> configs + env file + compose + deployment scripts
  -> scripts/cd/remote-deploy.sh
  -> per-service readiness/governance checks
  -> dated production evidence
```

`.github/workflows/cd.yml` 负责服务计划、镜像交付和部署编排；`scripts/cd/plan-services.sh` 决定本次需要部署的服务。依赖服务在 apiserver 之后部署的顺序由契约测试保护，
但一次 workflow 成功只能证明该 run 和该 SHA。

## 3. 容器网络与端口

| 服务 | 容器入口 | Compose 暴露 | 边界 |
| --- | --- | --- | --- |
| qs-apiserver | 8080 HTTP、8443 HTTPS、9090 gRPC；配置虽保留 `healthz-port: 9091`，当前代码没有创建 9091 listener | 宿主机只把 8080/8443/9090 映射到 `127.0.0.1` 的 8081/9445/19090 | 业务公网流量必须经 Nginx；标准 gRPC Health 走 9090，不能为 9091 配置成功探针 |
| collection-server | 8080 HTTP、6060 profile | 仅 `expose` 到 Docker 网络 | 公网由 Nginx 终止并负载均衡；不应直接发布宿主机端口 |
| qs-worker | 9092 metrics/health/ready | 仅 `expose` 到 Docker 网络 | handler 无应用层认证，必须靠网络分段、Nginx ACL/鉴权或采集网络限制访问 |

三个服务连接外部 `qs-network` 和 `infra-network`。网络存在、跨机 overlay DNS、Nginx upstream、Prometheus 抓取路径和主机防火墙都不由 Compose 静态文件单独证明。

生产 Compose 的 apiserver host-port 回环限制由 `scripts/cd/test-production-compose-network-exposure.sh` ratchet；新增端口时必须同时更新该测试和安全文档。

## 4. 挂载与文件所有权

- 每个服务挂载独立 `/opt/qs-server/<service>/configs` 到 `/app/configs`。
- apiserver 额外挂载公网 TLS 证书、私钥与二维码目录。
- 三个服务都挂载 gRPC mTLS 目录；worker 和 apiserver 另挂载日志目录。
- `remote-deploy.sh` 对配置、证书、私钥和日志目录设置 owner/mode，并核验 gRPC 证书身份。
- 镜像内的默认文件不替代本次部署包；运行时以实际挂载和 env file 为准。

## 5. 网络暴露验收

至少检查：

1. `docker compose config` 展开后没有意外的 `0.0.0.0` host mapping；
2. Nginx 只代理允许的业务/观测路径；
3. worker 9092、collection 6060 不可从非授权公网访问；apiserver 9091 应确认没有 listener，若出现监听即视为配置/实现漂移；
4. mTLS 9090 只接受预期 CA/OU/服务身份，方法级 ACL 默认 deny；
5. Prometheus 抓取能从采集网络到达，而普通客户端不能借同一路径读取敏感指标；
6. 跨机 `infra-network` 的 DNS 和 MTU/防火墙在目标环境实测通过。

## 6. 验证入口

```bash
go test -count=1 ./internal/pkg/configcontract
bash scripts/cd/test-plan-services.sh
bash scripts/cd/test-prepare-package.sh
bash scripts/cd/test-production-compose-network-exposure.sh
bash scripts/cd/test-wait-worker-readiness.sh
bash scripts/cd/test-verify-worker-governance.sh
```

这些命令是仓库/脚本证据。真实环境仍需记录 `docker compose config` 的脱敏哈希、容器镜像 digest、监听地址、网络 ACL、Nginx 配置哈希和逐实例探针。

## 7. 未闭合 gap

- 当前 checkout 没有新的真实部署 run，不能继承历史副本数或主机拓扑为当前事实。
- 9092 的可达边界主要依赖部署网络；仓库缺少对所有目标主机防火墙/安全组的证据。9091 则是未被当前实现消费的配置债务，不应被写成待开放的监控端口。
- Compose 文件开头的主机与容量注释是期望/历史背景，不是实时资产台账。
- `latest` 是镜像变量的 fallback；生产验收必须要求 exact SHA/tag 与 digest，不能接受 fallback 作为证据。
